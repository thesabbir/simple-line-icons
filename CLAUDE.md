# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A line-icon webfont distributed as CSS, SCSS, LESS and font files (woff/woff2/ttf/eot/svg). There is no runtime application code — the repo is a Node build script that compiles a single source stylesheet into multiple formats and generates a cheat-sheet page.

## Commands

- `npm run build` — runs `node scripts/build`, then `postbuild` copies `dist/` into `docs/`.
- `npm test` — alias for the same build script; there is no real test suite, so "tests passing" just means the build succeeds.
- Requires Node (CI pins `14.5.0`) and the `less` dependency from `package.json`. Run `npm install` first.

## Source of truth vs. generated files

Edit **only** these:
- `src/styles/simple-line-icons.less` — the master stylesheet (class list + `content:` codepoint mappings + `@font-face`).
- `src/fonts/Simple-Line-Icons.*` — the actual font binaries (regenerated by an external tool such as IcoMoon, not by this repo).
- `src/svgs/*.svg` — individual icon source SVGs. **Not consumed by the build**; they exist so the font can be regenerated. Keep them in sync by hand when adding/removing icons.

Everything else is build output and must not be hand-edited: `dist/`, `docs/index.html`, and the legacy top-level `css/`, `scss/`, `less/`, `fonts/` directories (kept only for backwards-compatible import paths). Run the build instead of editing these; CONTRIBUTING's note about a `generate.php` on `gh-pages` is obsolete — the cheat sheet is now `docs/index.html` produced by the build.

## Build pipeline (`scripts/build.js`)

1. Wipe and recreate `dist/{styles,fonts,docs}`.
2. Copy `src/fonts/*` → `dist/fonts/`.
3. Compile `src/styles/simple-line-icons.less` into `dist/styles/` as `.less` (verbatim copy), `.css` (via `scripts/less2css.js`, a thin wrapper over the `less` renderer), and `.scss` (via `scripts/less2sass.js`).
4. `legacyDist()` — copy the three compiled stylesheets and the fonts back to the top-level `css/`, `scss/`, `less/`, `fonts/` folders.
5. `generateCheatSheet()` — regex-scrape `.icon-*:before { content: "…" }` rules out of the compiled CSS and render `scripts/cheatsheet.template.html` (substituting `{{version}}` from `package.json`, `{{fontCss}}`, `{{contents}}`) into `docs/index.html`.

`scripts/paths.js` centralizes every input/output path used above.

## LESS → SCSS conversion gotcha

`scripts/less2sass.js` is a vendored, modified copy of `ekryski/less2sass`; project-specific changes are tagged with `SIMPLE LINE ICONS DEVIATION:` comments. The important one: a LESS variable whose line ends with a `// default` comment is emitted as a SCSS `!default` variable. The three overridable variables at the top of `src/styles/simple-line-icons.less` (`@simple-line-font-path`, `@simple-line-font-family`, `@simple-line-icon-prefix`) rely on this — keep their trailing `// default` comments intact, and add the same comment to any new variable meant to be user-overridable. Also note the cheat-sheet scraper regex in `build.js` expects the compiled CSS to keep the literal `// default`-style comment markers, so don't reformat generated output by hand.

## Adding or changing an icon

1. Regenerate the font binaries in `src/fonts/` with the icon added/changed, and update `src/svgs/` to match.
2. Add the new class name to the `&name,` list and a corresponding `.@{simple-line-icon-prefix}name:before { content: "\eXXX"; }` rule in `src/styles/simple-line-icons.less`.
3. Run `npm run build` and commit the regenerated `dist/`, `docs/`, and legacy top-level folders along with the source changes (the build produces a lot of churn — that's expected and is committed).
4. Per CONTRIBUTING.md, include a screenshot of the icon in the PR. Never edit one stylesheet format directly to "fix" it — change the LESS source and rebuild so all formats stay consistent.

## Releasing

Bump `version` in `package.json` (it flows into the cheat sheet via `{{version}}`); `bower.json` carries its own version field. `History.md` is a hand-maintained changelog.
